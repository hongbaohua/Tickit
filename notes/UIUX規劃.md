## 一、整體視覺風格

### 設計語言
- **極簡線條風（Minimal Line）**：乾淨、現代、科技感
- 字體為主角，icon 最小化，留白即是設計
- 適合專業備考用途，呼應「效率」與「精準」

### 色彩系統

| 用途 | 色碼 | 說明 |
|------|------|------|
| 主色 | `#4F46E5` | Indigo，按鈕、Active 狀態、品牌色 |
| 主色深 | `#4338CA` | Hover / Active |
| 背景 | `#F1F5F9` | 頁面底色（淺灰藍） |
| 卡片背景 | `#FFFFFF` | 卡片白 |
| 側欄背景 | `#111827` | 深墨色側欄 |
| 文字主色 | `#111827` | 主要文字 |
| 文字次色 | `#6B7280` | 輔助文字 |
| 文字淡色 | `#9CA3AF` | 提示、標籤 |
| 成功綠 | `#10B981` | 答對、通過 |
| 警告黃 | `#F59E0B` | 中等、標記書籤 |

### 字體
- 系統字體堆疊：`-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`

## 二、版型架構

### 整體框架
```
[側欄 220px] | [主內容區 flex:1，最大寬 660px 置中]
```

- 側欄：固定高度 `position: sticky; top: 0; height: 100vh`，深色背景
- 主內容區：卡片式排版，每個功能區塊為獨立 `.card`

### 側欄（所有頁面共用）

```
Tickit logo（✓ icon + 標準字）

● 首頁
● 考生管理
● 管理者        ← 僅管理者帳號可見（JS 控制 display）
```

## 三、頁面規劃

### 3-1 首頁（index.html）

**狀態一：登入畫面（view-login）**
- Logo 區塊（✓ icon + Tickit 標準字 + Slogan）
- 輸入框：「用戶代號」
- 「進入系統 →」按鈕
- 若代號不存在 → 展開確認建立區塊（「建立帳號」/ 「重新輸入」）

**狀態二：測驗設定畫面（view-setup）**

*用戶列（user-bar）*
- 頭像字母（Avatar）+ 用戶代號
- 「✏ 修改名稱」按鈕（點擊展開 rename-form）
- 「登出」按鈕

*修改名稱表單（rename-form，預設隱藏）*
- 輸入新代號
- 錯誤提示（已被使用 / 空白）
- 「確認修改」 / 「取消」
- 成功後 Toast：「用戶代號已更新」
- 同步更新 sessionStorage 與頁面顯示

*Step 01：主題*
- `<select>` 下拉，從 manifest.json 自動產生

*Step 02：單元（topic 選擇後顯示）*
- 全選按鈕 + 縮圖/清單切換（≥5 個單元時顯示）
- 每個 checkbox-item 顯示：單元代號 Tag + 標題 + 題數徽章
- 已選單元計數（「已選 N / M 個單元，共 X 題」）

*Step 03：練習模式（topic 選擇後顯示）*
- 全部題目
- 隨機抽取 N 題（顯示數量輸入框）
- 只練習錯題（顯示提示說明）
- 攻克模式（顯示提示說明）
- ★ 反覆練習標記題目（顯示提示說明）

*開始測驗 →*（至少選一單元才啟用）

### 3-2 測驗頁（quiz.html）

#### 一般模式（all / random / wrong-only）

*進度卡片*
- 題號標籤（Q1 藍底）+ 總題數
- 主題 / 單元徽章
- 進度條（已完成比例）

*題組情境卡（若為「承上題」題型）*
- 「題組」標籤 + 「上一題情境」
- 情境文字

*題目卡片*
- Q{n} 徽章 + 題目文字
- ☆ 標記書籤按鈕（右上角，點擊切換 ☆/★）

*選項列表（options-list）*
- 每個選項：字母圓框 + 選項文字
- 點擊後標記為 `.selected`（靛藍左邊框）

*導覽列*
- ← 上一題（第一題隱藏）
- 已作答 N / M 題（中間）
- 下一題 → / 送出（最後一題）

*結果頁（view-results）*
- 甜甜圈圓餅圖（答對率 → 顏色）
- 評等：優秀（≥80%）/ 加油（≥60%）/ 需補強（<60%）
- 統計：答對題數 / 答錯題數 / 評等
- 弱點摘要（答對率 < 75% 的單元列表）
- 「答錯題目」展開區塊（預設展開）
- 「查看所有題目解析」展開區塊
- 返回首頁按鈕

#### 攻克模式（mastery）/ 標記練習（marked）

*進度標頭*
- 模式徽章（攻克模式 紅色 / 標記練習 橙色）
- 已攻克 N / M 題
- 剩餘 X 題
- 題目點陣（≤30 題顯示，各狀態顏色：灰=未到、靛=當前、橙=曾錯、綠=攻克）
- 綠色進度條

*「↩ 再練」徽章*（曾答錯過的題目才顯示）

*題目卡片 + 選項*（同一般模式）

*揭曉後*
- 選項顯示顏色（綠=正確、紅=錯誤選擇）
- 解析框（💡 解析：...）

*按鈕文字動態切換*
- 答對 → 「✓ 攻克！下一題 →」（綠色按鈕）
- 答錯 → 「✗ 再練！下一題 →」（紅色按鈕）

*完成畫面（view-mastery-complete）*
- 🎉 慶祝圖示
- 攻克題數 / 重練次數 / 首答答對率
- 返回首頁

### 3-3 考生管理頁（dashboard.html）

*Header banner*（深色漸層）

*選擇用戶*
- 文字輸入 + `<datalist>` 下拉補全 + 查詢按鈕
- 若從管理者頁面跳轉（`adminViewUser` sessionStorage），自動預填並載入

*測驗紀錄表格*
- 欄位：日期 / 主題 / 單元 / 答對 / 答對率（Badge 色碼）/ 回顧錯題
- 分頁（每頁 10 筆）
- 展開行：顯示該次錯題 + 解析

*主題分析 Tabs*（多主題時顯示）

*關鍵指標 4 格*
- 測驗次數 / 平均答對率 / 累計作答題數 / 最高答對率

*答對率趨勢圖*（Chart.js 折線，需 ≥ 2 次）

*弱點診斷 3 欄*
- 🔴 需要加強（< 60%）
- 🟡 尚可，可繼續加強（60–80%）
- 🟢 掌握良好（≥ 80%）
- 強化建議文字（優先複習哪些單元）
- 每單元需 ≥ 3 題才列入統計

*各單元答對率橫條圖*（Chart.js，依答對率升冪排列）

*高頻錯題 Top 10 表格*（答錯次數排名）

### 3-4 管理者頁（admin.html）— 新增

> 僅管理者帳號（`ADMIN_USERS`，定義於 config.js）可存取；否則顯示「無權限」提示。

*Header banner*（深色漸層，角落顯示「Admin」紅色徽章）

*統計摘要 3 格*
- 帳號總數 / 有測驗紀錄 / 從未使用（0 session）

*考生帳號管理卡片*
- 搜尋框（即時篩選用戶名稱）
- 表格欄位：用戶代號 / 建立日期 / 測驗次數 / 備註（管理者可見）/ 操作
- **測驗次數**：若 > 0，可點擊連結跳轉至 dashboard.html 並自動載入該考生
- **刪除**：任何帳號均可刪除（含有紀錄者顯示警告 confirm），管理者帳號不顯示刪除按鈕
- **備註**：每格顯示備註預覽 + ✏ 編輯按鈕

*備註 Modal*
- 標題顯示「備註 — {用戶名稱}」
- Textarea（可調整高度）
- 「儲存備註」/ 「取消」
- 儲存至 `localStorage["admin_notes"]`（JSON 物件，key 為 userId）
- 注意：備註儲存於瀏覽器本地，**跨裝置不同步**（未來可移至 Supabase 新表）

## 四、組件規範

### 按鈕
| 類別 | 樣式 | 用途 |
|------|------|------|
| `.btn-primary` | 靛藍漸層、白字 | 主要操作（開始、確認） |
| `.btn-ghost` | 無背景、灰框 | 次要操作（取消、返回） |
| `.btn-sm` | 較小 padding | 行內小按鈕 |
| `.btn-full` | 寬度 100% | 全寬主按鈕 |

### 卡片
- `.card`：白底、圓角 14px、細陰影、1.4rem padding
- `.card-top-accent`：頂部 3px 靛藍邊

### 徽章
- `.badge-green` / `.badge-yellow` / `.badge-red`：小型狀態標籤

### Toast（通知）
- 底部浮現，2.5 秒後消失
- 用於非阻斷式回饋：「已從第 N 題繼續」、「用戶代號已更新」等

### 進度條
- `.progress-bar-track` + `.progress-bar-fill`
- 一般模式：靛藍
- 攻克模式：綠色漸層

## 五、互動設計

### 中斷恢復
- 一般模式（all / random / wrong-only）：每次翻頁 / 答題後存入 `localStorage`
- 刷新或返回後自動恢復並顯示 Toast
- 攻克模式 / 標記練習：不支援中斷恢復，中斷後需重新開始

### 書籤標記（★）
- 任何模式下答題時均可標記
- 儲存於 `localStorage["bookmarks_{userId}"]`（Set 序列化）
- 在「★ 反覆練習標記題目」模式中載入

### 選項打亂
- 每次開始測驗時題目與選項均重新隨機打亂
- 末尾句號自動刪除

### 承上題（題組）
- 若題目具有 `group_context`，在題目卡片上方顯示情境卡

## 七、資料流與狀態管理

```
登入 (index.html)
  └→ sessionStorage["quizUser"] = { id, name }
     └→ 各頁面讀取以識別用戶身份
        └→ quiz.html: sessionStorage["quizSession"] = { questions, topic, units, userId, mode, sessionId }
           └→ localStorage["quiz_progress_{sessionId}"] = { idx, answers }  ← 一般模式中斷恢復
        └→ localStorage["bookmarks_{userId}"] = [questionId, ...]           ← 書籤
        └→ localStorage["admin_notes"] = { userId: "備註文字", ... }         ← 管理者備註
        └→ Supabase: quiz_sessions + question_results                        ← 長期紀錄
```

## 八、設計決策記錄

| 決策 | 原因 |
|------|------|
| 純前端不使用框架 | 部署於 GitHub Pages 靜態環境，無需 Node.js runtime |
| 書籤存 localStorage 不寫 DB | 標記是個人學習習慣，不需跨裝置同步，避免增加 DB 寫入量 |
| 管理者備註存 localStorage | 暫時方案，避免修改 DB schema；未來若需跨裝置同步再遷移至 Supabase |
| 攻克模式不支援中斷恢復 | 攻克邏輯包含動態佇列插入，狀態難以序列化，斷點後重來語意更清晰 |
| question_id 格式固定 | 已有歷史紀錄，修改格式會導致舊紀錄失效，永久保護 |
| 考生無密碼登入 | 降低使用門檻（備考工具），帳號名稱作為輕量識別即可 |
